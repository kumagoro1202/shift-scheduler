## 3. 公平性

### ⚠️ 実装状況

**結論**: 管理者視点では公平性アルゴリズムが実装されているが、**スタッフ視点では評価不可**。

#### 調査結果（管理者視点）

1. **最適化アルゴリズム**（01-docs/spec/REQUIREMENTS.md:313-370）
   - 3つの最適化モード:
     - バランス: 勤務回数とスキルの両方を考慮
     - スキル重視: 目標スキルスコアへの近似を優先
     - 日数重視: 勤務回数の均等化を優先
   - **スキル能力の平均化**（01-docs/spec/REQUIREMENTS.md:327-342）:
     > それぞれの時間帯において、配置される職員のスキル能力を平均化する。特に受付業務では医事能力を優先する。
   - **勤務回数の均等化**（01-docs/spec/REQUIREMENTS.md:340-344）:
     > 各職員の勤務回数を可能な限り均等にする

2. **制約条件**（01-docs/spec/REQUIREMENTS.md:347-370）
   - ハード制約（必ず守る）:
     - 休暇登録のある日は勤務させない
     - 職員タイプで配置不可の業務エリアには配置しない
     - 各時間帯の必要人数を満たす
   - ソフト制約（可能な限り守る）:
     - 連続勤務日数の制限
     - 週末勤務の配分
     - スキルスコアのバランス

#### 4. 交代・休み申請機能

**目的**: スタッフ同士でシフトの交代や急な休みの調整ができるようにする

**実装内容**:
- **交代申請フロー**:
  1. スタッフAが「2/15（水）のシフトを交代したい」と申請
  2. システムが交代可能なスタッフBをリストアップ（職員タイプ、勤務可能時間帯でフィルタ）
  3. スタッフAがスタッフBに交代依頼を送る
  4. スタッフBが承諾 or 拒否
  5. 承諾された場合、管理者に承認依頼が送られる
  6. 管理者が最終承認
- **急な休み申請**:
  - 体調不良等で当日休む場合、アプリから申請
  - 管理者に即座に通知（LINE or メール）
  - 管理者が代わりのスタッフを手配

**データモデル**:
```sql
CREATE TABLE shift_swap_requests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    requester_id INTEGER NOT NULL,       -- 交代依頼者
    target_id INTEGER,                   -- 交代相手（まだ決まっていない場合はNULL）
    shift_date DATE NOT NULL,
    status TEXT NOT NULL,                -- 'pending', 'accepted_by_target', 'approved', 'rejected'
    reason TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (requester_id) REFERENCES employees(id),
    FOREIGN KEY (target_id) REFERENCES employees(id)
);
```

  - Google Calendar、Outlook、iPhoneカレンダーに登録可能
- **カレンダー購読URL**:
  - 固定URL（例: https://shift.example.com/staff/12345/shifts.ics）を発行
  - このURLをカレンダーアプリに登録すると、自動で同期される

**参考実装**:
```python
# 02-src/backend/routes/staff.py
from icalendar import Calendar, Event
from datetime import datetime

@bp.route('/me/shifts.ics', methods=['GET'])
def export_shifts_ical():
    employee_id = get_current_employee_id()
    shifts = get_employee_shifts(employee_id)

    cal = Calendar()
    cal.add('prodid', '-//Shift Scheduler//mxm.dk//')
    cal.add('version', '2.0')

    for shift in shifts:
        event = Event()
        event.add('summary', f'勤務 ({shift.pattern_symbol})')
        event.add('dtstart', shift.start_datetime)
        event.add('dtend', shift.end_datetime)
        event.add('location', shift.area)  # 'リハ室' or '受付'
        cal.add_component(event)

    return cal.to_ical(), 200, {'Content-Type': 'text/calendar'}
```

## まとめ

### 現状の評価

shift-scheduler-claude は **管理者（院長・事務長）向けのシフト作成ツール**としては非常に優れている。最適化アルゴリズム、レスポンシブデザイン、データバックアップ等、管理者に必要な機能は十分に実装されている。

しかし、**スタッフ（従業員）視点では、使える機能が一切存在しない**。スタッフは以下のような状況に置かれる:

1. **希望シフトを提出できない** → 管理者に口頭またはメモで伝える必要がある
2. **自分のシフトを確認できない** → 管理者に紙で印刷してもらうか、口頭で教えてもらう必要がある
3. **シフト確定の通知がない** → 自分で管理者に聞きに行く必要がある
4. **交代・休み申請ができない** → 管理者に電話して、交代相手も自分で探す必要がある
5. **スマホから見られない** → PCがないと何もできない
6. **公平性が分からない** → 自分のシフトが公平かどうか判断できない

### 推奨される改善方向

**短期的には**、以下の3つの機能を最優先で実装すべき:

1. **スタッフ用画面**（ログイン、自分のシフト確認）
2. **希望シフト提出機能**
3. **シフト確定通知機能**（LINE推奨）

この3つがあれば、スタッフのUXは劇的に改善される。

**中長期的には**、交代・休み申請機能、公平性の可視化、カレンダー連携等を追加し、スタッフが「使いやすい」「公平だ」と感じられるシステムにすべきである。
