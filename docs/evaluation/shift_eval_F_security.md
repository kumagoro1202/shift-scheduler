## 総合評価

**セキュリティリスクレベル: 中（ローカルデスクトップ用途として）**

本システムはFlask + React + PyWebViewによるローカルデスクトップアプリケーションであり、`127.0.0.1:5000`にバインドされたlocalhostオンリーの構成。ネットワーク露出を前提としない設計であるため、現在の用途では許容可能なリスクレベルである。ただし、**医療従事者の個人情報（PII）を扱う**観点から、データ保護・ログ管理に重大な改善余地がある。

---

## 1. セキュリティ良好な点

### 1.1 SQLインジェクション対策: 優秀
- 全データベースクエリがSQLAlchemy ORMのパラメタライズドクエリを使用
- **生SQLクエリはゼロ**。ORM設計によりSQLi攻撃を構造的に排除
- 根拠: `02-src/backend/routes/employees.py:24-28`, `shifts.py:30-61`, `absences.py:32-49`

### 1.2 入力バリデーション: 包括的
- 全APIエンドポイントで必須フィールド・型・範囲の検証を実装
- 職員名の必須チェック (`employees.py:75-79`)
- 職員タイプのEnum検証 (`employees.py:82-86`)
- スキルスコア0-100範囲検証 (`employees.py:104-106`)
- 日付フォーマット検証 (`absences.py:32-35`)
- 整数型変換のエラーハンドリング (`absences.py:45-49`)
- 年月範囲検証: 月1-12, 年2000-2100 (`generate.py:184-192`)

### 1.3 エラーハンドリング: 適切
- グローバル例外ハンドラが内部詳細を隠蔽し、一般的なエラーメッセージのみ返却 (`app.py:104-109`)
- スタックトレースはログにのみ記録、クライアントには非開示
- ユーザー向けエラーメッセージは平易な日本語（ITリテラシーの低いユーザーへの配慮）

### 1.4 Flaskサーバーバインド: 安全
- `127.0.0.1`にのみバインド、外部ネットワークからのアクセスを遮断 (`main.py:129`)
- `debug=False`, `use_reloader=False`で本番設定 (`main.py:215`)

### 1.5 XSS対策: 優秀
- React JSXの自動エスケープにより構造的にXSSを防止
- `dangerouslySetInnerHTML`, `innerHTML`, `eval()`, `document.write()`の使用なし
- 全27フロントエンドファイルをスキャン済み、危険パターンゼロ

### 1.6 パストラバーサル対策: 安全
- `send_from_directory()`使用によりパストラバーサルを防止 (`app.py:71-73`)
- バックアップファイルは`pathlib.Path`で安全にパス構築 (`backup.py:75-78`)

### 1.7 データベースセッション管理: 適切
- 全ルートで`try/finally`によるセッションクローズ (`employees.py:46-47`等)
- エラー時のトランザクションロールバック実装 (`employees.py:135-136`等)

### 1.8 コマンドインジェクション対策: 安全
- `subprocess.run()`はリスト引数で使用（`shell=True`不使用） (`build.py:29`)

## 4. 医療系セキュリティ基準の考慮

本システムは**診療所（医療施設）の従業員情報**を扱うため、以下の観点が重要：

### 4.1 個人情報保護法（APPI）との関係
- **該当PII**: 職員氏名、勤務パターン、スキルスコア、休暇情報
- **現状**: 暗号化なし、アクセス制御なし、ログにPII漏洩
- **要改善**: データの暗号化（V-04）、PII除外ログ（V-06）、アクセス制御

### 4.2 医療情報システムの安全管理ガイドライン（厚労省）との関係
- **バックアップ保護**: 現状は平文コピー → 暗号化必須（V-07）
- **監査証跡**: 現状なし → 操作ログの記録が必要（V-17）
- **アクセス制御**: 単一ユーザーだが、共有PCの場合は問題

## 6. 総括

### 強み
- **SQLインジェクション耐性**: ORM徹底使用で構造的に安全
- **XSS耐性**: React自動エスケープ + 危険パターンゼロ
- **入力バリデーション**: 全エンドポイントで包括的検証
- **エラーハンドリング**: 内部情報の非開示が徹底
- **ローカルバインド**: `127.0.0.1`限定で外部遮断

### 弱み
- **暗号化不足**: DB・バックアップ・ログがすべて平文
- **PII保護不足**: 医療従事者の氏名がログに平文記録
- **CORS無制限**: デスクトップアプリに不要な`Access-Control-Allow-Origin: *`
- **SECRET_KEY固定値**: セッション改ざんリスク

### 最終判定
**ローカルデスクトップ専用アプリとして「条件付き合格」**。Phase 1（約5時間の対応）を実施すれば、診療所内での単一PC利用には十分なセキュリティレベルに到達する。ネットワーク公開は認証・RBAC実装完了まで厳禁。
