# ステークホルダー評価: A. シフト管理者視点

**評価日**: 2026-02-07
**評価対象**: shift-scheduler-claude（診療所向けシフト作成システム）
**バージョン**: v1.5.0

---

## 評価者ペルソナ

- **年齢**: 50代
- **職種**: 診療所の事務長（シフト管理担当）
- **ITリテラシー**: 低（Excel操作は可能だが、専門的なソフトウェアの経験なし）
- **これまでの業務**: 月に1回、Excelでシフト表を手作業で作成
- **システムへの期待**: 「操作が簡単で、誰でも使える」「トラブルが起きても自分で対処できる」
- **不安点**: 「難しいパソコン用語が出てきたらわからない」「間違えてデータを消したらどうしよう」

## 良い点

### 1. **操作フローが直感的で迷わない**


- ナビゲーションが画面左側に常時表示され、今どこにいるかがすぐわかる
- 「ホーム」→「職員管理」→「休暇管理」→「シフト生成」→「シフト表示」という自然な順序で並んでいる
- 各メニューにアイコンがついているので、文字が読めなくても視覚的に判別できる

**評価**: ✅ Excel でシフト表を作る時の手順（職員リスト作成 → 休暇入力 → シフト組み → 確認）とほぼ同じなので、違和感なく使える

## 不足点・問題点

| 問題 | 影響度 | 根拠 |
|------|--------|------|
| **1. シフトのExcel出力機能が実装されていない** | 高 | 01-docs/spec/REQUIREMENTS.md:23「Excel出力」と記載されているが、実装コードが見当たらない。現場では「印刷してホワイトボードに貼る」「紙で配る」という運用が一般的。Excel出力がないと、実務で使えない。 |
| **2. 印刷用レイアウトがない** | 高 | 画面表示のまま印刷すると、ナビゲーションやボタンも印刷されてしまう。印刷専用のレイアウト（ヘッダー・フッターなし、A4横向き最適化）が必要。 |
| **3. 月次・週次の切り替えができない** | 中 | 02-src/frontend/src/pages/ShiftsPage.tsx では月度（21日〜翌月20日）のみ表示。週次でシフトを確認したい場合（例: 今週のシフトだけ確認）に不便。 |
| **4. 職員の「希望休暇」登録機能がない** | 中 | 01-docs/spec/REQUIREMENTS.md:729 に「職員からの希望シフト登録機能」が「今後の拡張性」として記載されているが未実装。実務では「この日は休みたい」という希望を先に集めてからシフトを組む。現状は管理者が手動で休暇登録する必要がある。 |
| **5. 法定労働時間のチェック機能がない** | 高 | 労働基準法の「週40時間」「月の残業時間上限」をシステムがチェックしていない。現場では「このシフトだと残業時間がオーバーしてないか？」を手計算で確認する必要がある。 |
| **6. シフトの手動編集後に再最適化する機能がない** | 中 | 02-src/frontend/src/components/ShiftEditModal.tsx で手動編集はできるが、編集後に「この変更で全体のバランスが崩れてないか？」を再計算する機能がない。 |
| **7. バックアップの自動実行設定がUIにない** | 中 | 01-docs/manual/USER_MANUAL.md:442 に「自動バックアップ」と記載されているが、UI上で「毎日自動バックアップする」などの設定ができない。手動バックアップのみ。 |
| **8. ダブルクリック起動の.exeファイルがまだ完成していない** | 高 | 01-docs/spec/REQUIREMENTS.md:7 に「ダブルクリックで起動可能な単一実行ファイル（.exe）」と記載されているが、現状は開発モードでの起動手順（Flask + React）のみ。エンドユーザーが使うには、.exeのビルドが必須。 |
| **9. 「前回と同じシフト」を参考にする機能がない** | 中 | 実務では「先月とほぼ同じシフトでいいから、微調整だけしたい」というケースが多い。現状は毎回ゼロから生成するため、「前月のシフトをコピーして編集」という機能があると便利。 |
| **10. エラー発生時の「元に戻す」機能がない** | 低 | シフト生成に失敗した時、「既存シフトを削除」設定にしていると元に戻せない。バックアップから復元はできるが、初心者には難しい。 |

## 改善提案

| 提案 | 優先度 | 理由 |
|------|--------|------|
| **1. Excel出力機能の実装** | 最優先 | 現場では「紙で配る」「ホワイトボードに貼る」という運用が一般的。Excel出力がないと、システムが実務で使われない。 |
| **2. .exeファイルのビルドと動作確認** | 最優先 | 「ダブルクリックで起動」がシステムの最大の売りなのに、.exeがないとエンドユーザーが使えない。PyInstallerでのビルド手順の確立が急務。 |
| **3. 印刷用レイアウトの追加** | 高 | ブラウザの「印刷プレビュー」で、ナビゲーションやボタンを非表示にする CSS を追加する。A4横向きで最適化。 |
| **4. 法定労働時間チェック機能** | 高 | シフト生成時に「週40時間超過」「月の残業時間上限超過」を自動チェックし、警告を表示する。労働基準法違反のリスク回避。 |
| **5. 職員が休暇希望を入力できるフォーム** | 中 | 職員専用の簡易ページ（パスワード不要、名前選択のみ）で「この日は休みたい」を入力できるようにする。管理者は集まった希望を確認して承認。 |
| **6. 週次表示モードの追加** | 中 | 「今週のシフト」「来週のシフト」を簡単に確認できるモード。月度表示だと30日分が表示されて見づらい。 |
| **7. 前月シフトのコピー機能** | 中 | 「前月と同じシフトをベースに、微調整だけしたい」というニーズに対応。シフト生成画面に「前月のシフトをコピー」ボタンを追加。 |
| **8. バックアップ自動実行の設定UI** | 低 | 「毎日自動バックアップ」「シフト生成前に自動バックアップ」などの設定を UI から変更できるようにする。 |
| **9. 「元に戻す」機能（Undo）** | 低 | シフト生成失敗時に、「既存シフトを削除」前の状態に戻せるようにする。一時的なバックアップを自動作成。 |
| **10. チュートリアル動画の埋め込み** | 低 | ホーム画面に「使い方動画（3分）」を埋め込む。文字より動画の方が理解しやすい人向け。 |

## 総合評価

### ✅ 優れている点

1. **ITリテラシーの低いユーザーへの配慮が徹底されている**
   - 平易な日本語のエラーメッセージ
   - ホーム画面に組み込まれた「使い方ガイド」
   - スライダーUIによる直感的な入力

2. **操作フローが自然で迷わない**
   - 左サイドバーのナビゲーションで現在地がわかる
   - 「職員登録 → 休暇登録 → シフト生成 → 確認」という自然な流れ

3. **エラー発生時の対処方法が明確**
   - 「何をすべきか」まで書かれたエラーメッセージ
   - 制約違反の詳細表示（どの日のどのエリアで人が足りないか）

### ❌ 課題

1. **Excel出力・印刷機能の欠如**
   - 現場で最も重要な「紙で配る」運用ができない

2. **.exeファイルがまだ完成していない**
   - 「ダブルクリックで起動」というコンセプトが実現できていない

3. **法定労働時間チェックがない**
   - 労働基準法違反のリスクがある

### 📊 学習コストの評価

**初回起動から最初のシフト生成まで**: 約30分（想定）
- ホーム画面の「使い方」を読む: 5分
- 職員を5名登録: 10分
- 休暇を3件登録: 5分
- シフト生成: 5分
- 結果確認: 5分

**評価**: ✅ ITリテラシーの低いユーザーでも、1時間あれば基本操作をマスターできる。Excelでシフトを手作業で作るよりは圧倒的に速い。

## まとめ

shift-scheduler-claude は、「ITリテラシーの低い診療所の事務長」をターゲットユーザーとして設計されており、その点では非常に優れたシステムです。特に、**エラーメッセージの親切さ**、**ホーム画面のガイド**、**直感的なUI** は、現場で高く評価されるでしょう。

ただし、**Excel出力機能**と**.exeファイル**が未完成である点は、実務投入の大きな障壁です。これらが完成すれば、「診療所のシフト管理を劇的に効率化するツール」として、十分に現場で受け入れられるポテンシャルがあります。

**推奨される次のステップ**:
1. .exeファイルのビルド手順を確立し、実際に動作確認する
2. Excel出力機能を実装する（openpyxl を使った .xlsx ファイル生成）
3. 印刷用レイアウトを追加する
4. 法定労働時間チェック機能を追加する

これらが完了すれば、**実務投入可能なMVP（Minimum Viable Product）** となります。
